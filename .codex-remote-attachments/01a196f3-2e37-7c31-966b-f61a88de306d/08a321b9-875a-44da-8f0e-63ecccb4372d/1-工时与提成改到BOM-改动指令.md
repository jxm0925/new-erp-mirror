# 工时与提成改到 BOM：改动指令

## 0. 背景和目标

现在工序工时存在工艺路线上，提成比例来自绑定在路线上的提成模板（路线指定模板 → 默认模板）。公司有几千款定制品，工时、提成各不相同，按现有结构就得建几千条路线。

**目标：**
- 路线只管工序顺序、交接、质检、入库这些执行规则，同一种工艺的产品共用一条路线。
- 工时放在实际生产对象的 BOM 上。
- 提成比例统一放在最终整机的 BOM 上。

整体按你提交的方案执行。本文件是在该方案基础上的补充和明确，两者冲突时以本文件为准。

**系统还没上线，不考虑旧数据和旧工单兼容。** 你方案里「旧资料衔接、已有工单保留原算法」这部分不做。不需要新旧规则并存，也不需要过渡逻辑，直接按新规则改。

**先预检，后开发：** 开发前请先只读核对现有代码和数据库，输出一份预检报告。报告里包括：与现有逻辑的冲突点、表结构 SQL 草案、需要我确认的问题。我确认后再开工。

## 1. 资料怎么分工

| 资料 | 负责的内容 |
|---|---|
| 工序档案 | 下料、焊接、打磨、总装、试水、打包、装车等基础工序 |
| 工艺路线 | 工序顺序、交接、质检、入库等执行规则；**不再维护工时和提成** |
| 半成品 BOM（架子、电箱等） | 材料用量、选用路线、各工序的标准工时 |
| 整机 BOM | 整机用料、选用路线、整机工序的标准工时，以及**整机和下属所有半成品的全部提成比例** |
| 工单 | 生成时保存执行依据：路线结构、BOM 版本、标准工时、整套提成方案 |
| 报工记录 | 实际人员、用料、工时、产出（保持不变） |

路线上的工时字段（`standard_minutes`、`setup_standard_minutes`、`unit_standard_minutes`）、提成字段（`performance_rate`），以及提成模板按路线绑定的逻辑，直接去掉。路线编辑页同步删除这些内容，不保留只读的旧字段。

## 2. BOM 改造

### 2.1 选用路线

BOM 上增加「选用路线」，必须是适用于这个产出物料的路线。生成工单时，默认使用 BOM 选用的路线；生产主管仍可在「调整工单」里换路线，换路线后要按新路线重新带出工时、匹配提成。

### 2.2 工序工时

- 选择路线后自动带出生产工序，逐道填写准备工时和单件工时。
- 标准人时 = 准备工时 + 单件工时 × 数量。例如准备 0.5 小时、每件 2 小时、做 10 件，标准人时就是 20.5 小时。
- 标准工时只用于计划和效率对比，不替代实际报工工时。
- 工时可以不填。不填时显示「未设标准工时」，不影响生产，也不影响提成。
- 整机 BOM 中可以展开查看半成品 BOM 的工时（只读）。

### 2.3 整机提成

- 自动汇集「整机自己的工序」和「下属各级半成品的工序」，逐行填写比例。
- **每一行用「归属位置 + 工序」唯一识别。** 归属位置按 BOM 结构的路径区分：整机本身，或者整机 BOM 第几行的半成品，再往下第几行……。不能只按工序名或工序编号匹配：架子焊接和电箱焊接必须分开；同一种半成品用在两个装配位置，也要能分开填。
- 每行有三种状态：
  - **已填比例：** 正常计算。
  - **明确不计提成：** 按 0 处理。
  - **未配置：** 提醒补齐，并阻止正式结算。不阻止生产。
- **一个比例对应这台整机在这个位置的全部用量。** 例如一台用 2 个架子，「架子焊接 1%」就是这 2 个架子的焊接提成合计，不能每个架子各算一次 1%。
- 试水、打包、装车这些发货作业的提成也在整机 BOM 里配置，和生产工序放在同一张表里。

### 2.4 取值顺序和批量维护（几千款产品必须有）

比例按下面的顺序取值：
1. 这份 BOM 自己填的值；
2. 没填，取产品分类的默认提成模板；
3. 再没有，取全局默认模板；
4. 都没有，算「未配置」。

模板保留为「快速填入」工具，原来按路线绑定的方式改为按产品分类绑定。填入或按分类自动带入以后，工单保存的是实际取到的比例和来源，以后改模板不追溯已有工单。

批量工具：
- 按分类，或按勾选的多份 BOM，批量套用模板。
- Excel 导出、导入 BOM 的工时和提成，导入前先预览差异。
- 复制 BOM 时，材料、路线、工时、提成一起复制。

### 2.5 半成品单独销售

架子、电箱如果自己就是销售订单上的商品，没有上级整机可以取比例，这时取它自己 BOM 里的提成配置。所以半成品 BOM 也要能配置自己工序的提成，只在单独销售时使用。

### 2.6 权限

提成比例属于敏感资料，新增权限：
- `master.bom.performance.view`：查看提成比例；
- `master.bom.performance.edit`：编辑提成比例。

没有查看权限的人看不到提成区域，接口也要过滤掉比例字段。工时不受这两个权限限制。新权限不自动分配给任何角色，上线时手工授权。

## 3. 特殊定制单（定制 BOM）（必须做）

特殊定制单不建 BOM 主档，由技术在工单上调整定制 BOM（`TechService`）。改造要求：
- 技术打开定制 BOM 时，自动带出基础 BOM 的工时和整套提成，可以逐项修改。
- 修改提成需要 `master.bom.performance.edit`；没有这个权限的技术只能改材料和工时，提成沿用基础 BOM。
- 定制 BOM 里替换了半成品（例如标准架换成定制架），对应位置的提成行要跟着更新。新半成品的工序按它自己的 BOM 和路线带出，未配置的行标出来。
- 下发车间时，定制 BOM 的工时和提成一起保存到工单，之后不再改变。
- 有提成行未配置，也允许下发，但要醒目提示；正式结算时拦截。

这样，大多数定制单不用新建任何资料，只有会重复销售的款才建正式 BOM。

## 4. 工单执行依据

- 工单生成或下达时，把路线结构和 BOM 的工时合并后存到工单工序上，同时保存整套提成方案：BOM 版本、每行的归属位置、工序、比例、取值来源（BOM / 分类模板 / 全局模板 / 未配置 / 明确为 0）。
- 半成品工单保存自己的工时和实际生产记录。生产时不需要确定最终提成，领用到整机后，按整机工单保存的方案取比例。
- 半成品工单不再保存提成比例。

## 5. 提成计算

需要同步修改的地方：
- `PerformanceStatsService`（订单提成）
- `PerformanceLedgerService`（出库结算台账）
- 发货包装作业的提成

### 5.1 整机自己的工序

计提金额 × 整机方案里对应行的比例，再按工序内人员份额分配。已有固定份额的沿用；没有的，按实际工时占比分。金额口径不变：折后商品含税金额，不含运费，不含另收的包装费。

### 5.2 半成品工序

**算法：**
- 比例取最终整机方案中「这个位置 + 这道工序」那一行；
- 人员和工时，按现有库存批次追溯找到实际生产的半成品工单。

**分摊规则：**
- 一批做 100 个，领出 10 个，就只归集这 10 个对应的工时和提成；剩下的以后被领用时继续归属。
- 一个位置用了多个、来自不同批次时，按各批次实际用量占比分配这一行的比例，合计不能超过这一行的比例。
- 多级半成品（例如电箱装进架子）按 BOM 路径逐级追溯。

**没有生产来源的：** 期初库存、外购的半成品，显示「无生产记录」，不虚构人员和提成，这一行的提成不发放。

**整机确实还要额外加工的**（例如在整机上补焊），作为整机自己的工序单独设置、单独计工时和提成，不和半成品的焊接混在一起。

### 5.3 发货作业（试水、打包、装车）

- 发货作业的提成比例改为从整机工单保存的方案读取，不再读路线节点或模板。
- 直接卖库存整机时，按序列号或批次找到当初生产它的工单，沿用那张工单的方案。
- 找不到生产来源的，提示「无生产方案」，并阻止正式结算。

### 5.4 结算拦截

- 有未配置的提成行、找不到生产方案时，订单提成显示「待补齐」，不能正式结算。
- 只是展示金额、不能结算。
- 原有的「订单商品全部发货后才可结算」规则继续保留。

## 6. 进度显示

260L 这类整机的进度仍然显示完整链条：下料 → 焊接 → 打磨 → 总装 → 试水 → 打包 → 装车。

- 由半成品工单生产的环节，整机上显示半成品的生产或供料进度。实际报工只在子工单上报一次，整机上不重复报工。
- 整机自己额外加的加工工序，正常显示和报工。

## 7. 分阶段实施

**第一阶段（解决几千条路线的问题）：**
- BOM 选用路线、工序工时、整机提成，覆盖整机自己的工序和发货作业；
- 取值顺序、批量工具、权限；
- 定制 BOM 也能改工时和提成；
- 工单保存完整方案；
- 整机自己工序和发货作业的提成按新规则计算；
- 去掉路线上的工时、提成，以及按路线绑定模板的逻辑。

**第二阶段：**
- 半成品工序的提成归到最终整机，含跨批次、跨设备分摊，多个同类半成品合计，多级追溯；
- 进度显示调整。

第二阶段完成前，整机方案中半成品位置的提成行只显示，不参与计算，并标注「第二阶段启用」。半成品的工时和人员统计照旧。

## 8. 数据库

- 按项目规则，已有表直接修改原迁移文件里的 CREATE_SQL；新表各建一份完整的初始建表迁移文件。
- 删除的字段也直接从 CREATE_SQL 中去掉。
- 另外给出现有测试库要执行的 ALTER SQL（包括删列），新列用 AFTER 放到与 CREATE_SQL 一致的位置，保证 `erp:verify-migration-schema` 能通过。不需要写数据回填。
